# Security

Report vulnerabilities privately to the repository owner (GitHub security advisory
or direct message). Include the version (`/healthz`), configuration without secrets,
and steps to reproduce. Do not open a public issue for an unfixed vulnerability.

## What the gateway can and cannot do

- It forwards requests to one fixed upstream (`GO_BASE_URL`) and returns the answers.
  It never runs commands, tools or code from a model's output, and has no code that
  writes files other than its own database. A prompt cannot make it read or change
  anything on the server.
- It listens on `127.0.0.1` only. The HTTPS proxy (Caddy) is the only public entry.

## Secrets

| Secret | How it is protected |
|---|---|
| Gateway API keys (`sk-gr-...`) | 256-bit random; stored only as SHA-256 hashes; shown once at creation. |
| Admin password | Generated by the setup scripts; verified with Argon2id; stored in `.env`. |
| Admin sessions | HttpOnly, `SameSite=Strict`, `Secure` on HTTPS; 12-hour lifetime; hashed in the database; cleared on restart. |
| OpenCode Go key | Saved in the dashboard; stored in the SQLite database because it must be sent upstream. Never returned by any API, written to logs, or shown in errors. |

Protect `.env`, `data/` and every backup like a password: they contain the Go key,
request logs and key hashes. They are excluded from Git and Docker builds. The
Windows installer restricts the folder to Administrators and SYSTEM; on Linux the
setup helper creates `.env` with mode `600`.

If the Go key leaks, rotate it in the OpenCode console and save the new one in
**Setup & settings**. If a gateway key leaks, revoke it in **API keys**.

## Built-in protections

- Dashboard: CSRF token on every change, origin check against `PUBLIC_URL`, strict
  Content Security Policy, no external scripts or fonts, `no-store` caching.
- Admin login: 10 attempts per minute per client address; at most two password
  checks run at once.
- API keys: optional expiry, requests-per-minute limit, allowed-model list and
  spending caps per hour, day and month, so one leaked or runaway key cannot use
  the whole Go plan.
  Revocation stops new requests immediately (streams already running finish).
- Requests without a valid key are rejected before any upstream call and are not
  stored, so anonymous traffic cannot fill the database.
- Request bodies must arrive within a deadline and fit `MAX_BODY_BYTES`; a client
  cannot hold a model slot while slowly uploading.
- Upstream errors are passed through with the Go key redacted.

## Your responsibilities

- Serve the gateway only over HTTPS with `PUBLIC_URL=https://...` and `COOKIE_SECURE=true`
  (the install scripts do this).
- Give each application its own key; never share the admin password or the Go key.
- Request logs store prompts and answers by default (media removed, 64 KiB cap,
  30-day retention). Set `LOG_BODIES=false` if that data is sensitive.
- Keep the operating system patched and restrict remote-administration ports
  (RDP 3389, SSH 22) to trusted addresses.
- Only administrators should be able to edit `.env`, `GO_BASE_URL` or `config/models.json`.
- OpenCode workspace privacy settings, regional limits and plan terms still apply;
  the gateway does not bypass them.
